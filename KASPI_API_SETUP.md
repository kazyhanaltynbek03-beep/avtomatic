# Kaspi API — QOR ERP

## Подключение и безопасность
1. В веб-кабинете продавца Kaspi откройте **Настройки → Токен API → Сформировать**.
2. В QOR откройте **Управление → Интеграции → Kaspi**, выберите API-аккаунт и вставьте токен. QOR хранит его зашифрованно на сервере; токен не возвращается браузеру и не должен попадать в GitHub, переписку или скриншоты.
3. Нажмите «Проверить подключение». Для теста выполняется небольшой read-only запрос заказов.
4. Если токен попадал в изображение или сообщение, отзовите его в Kaspi и сформируйте новый.

## Реализованные вызовы Kaspi API
- Проверка соединения и чтение заказов с пагинацией и временными окнами.
- Чтение состава заказа, связанных товарных данных и сопоставление с merchant product.
- Получение карточки заказа и состава заказа; синхронизация включает доступные Kaspi атрибуты и данные покупателя, если API их возвращает.\n- Изменение статуса заказа для поддерживаемых Kaspi состояний; операция требует явного подтверждения в интерфейсе.
- Получение списка категорий, характеристик категории и разрешённых значений.
- Асинхронная отправка карточек товара (1–100 карточек за запрос), проверка статуса и получение результата импорта.

## Доступ QOR API для каталога
- `GET /api/accounts/{id}/kaspi/orders/{order_id}`\n- `GET /api/accounts/{id}/kaspi/orders/{order_id}/entries?page_size=100`\n- `GET /api/accounts/{id}/kaspi/catalog/categories`
- `GET /api/accounts/{id}/kaspi/catalog/attributes?category={category_code}`
- `GET /api/accounts/{id}/kaspi/catalog/attribute-values?category={category_code}&attribute={attribute_code}`
- `POST /api/accounts/{id}/kaspi/products/import` с JSON-телом `{"products":[...]}`
- `GET /api/accounts/{id}/kaspi/products/import/{import_code}`
- `GET /api/accounts/{id}/kaspi/products/import/{import_code}/result`

Все маршруты требуют авторизованной сессии QOR и проверки доступа пользователя к компании; создание товара дополнительно требует права записи по интеграциям. Токен продавца остаётся на backend.

## Что Kaspi не предоставляет этим seller API
- Для публикации цен и остатков Kaspi документирует XML-прайс-лист, который продавец размещает по HTTP/HTTPS URL в кабинете. Это отдельный feed-механизм, а не операция изменения цены/остатка в REST API.
- Финансовые и взаиморасчётные отчёты не перечислены среди документированных операций seller API. Их следует выгружать из кабинета и импортировать в QOR через CSV/XLSX. Не показывать их как «синхронизированные через API».
- Наличие API токена не гарантирует доступ ко всем методам: Kaspi может ограничивать операции правами конкретного магазина.
