# Подготовка VPS: отчёты без ожидания при открытии

## Что уже включено в Compose

- PostgreSQL хранит данные в постоянном Docker volume.
- Полный отчётный кэш включён в Compose. Отдельный процесс готовит типовые периоды заранее; web запускается после завершения первоначального прогрева.
- Повторные открытия читают снимок из базы. Новый произвольный диапазон дат вычисляется при первом запросе и сохраняется для следующих открытий.
- Стандартные диапазоны включают сегодня, вчера, неделю, прошлую неделю, месяц, прошлый месяц, квартал, полугодие, год, прошлый год и последние 370 дней.
- Перед прогревом Compose применяет миграции и создаёт Owner из .env; пул каждого контейнера ограничен пятью соединениями плюс пятью дополнительными.

## Первый запуск

1. Установить Docker Engine и Compose v2, скопировать проект на VPS.
2. Создать .env из .env.example; задать длинные уникальные POSTGRES_PASSWORD, OWNER_PASSWORD, CREDENTIAL_ENCRYPTION_KEY и COOKIE_SECURE=true.
3. Поставить HTTPS reverse proxy перед 127.0.0.1:8000.
4. Выполнить docker compose up --build -d. Web станет доступен после прогрева; затем проверить docker compose ps и /api/health.
5. Подключить магазины и дождаться синхронизации. Кэш готовит отчёты из уже сохранённых данных; свежесть зависит от успешной синхронизации маркетплейсов.

Первый произвольный диапазон нельзя заранее рассчитать для всех возможных дат; после первого расчёта он сохраняется. Полные отчёты могут занимать больше места в PostgreSQL, чем краткие KPI-снимки.

Для восстановления сначала восстановить PostgreSQL и /srv/uploads, затем запустить Compose. Не включать DEMO_MODE на базе с рабочими данными.
