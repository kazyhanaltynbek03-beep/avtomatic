# QOR — изменение логистики (условная схема клиента)

Изменён расчёт недельного WB-отчёта. Поле WB `deliveryService`/`deliveryRub` рассматривается как общий логистический конверт. `rebillLogisticCost` выделяется как входящая в него дополнительная часть; больше не прибавляется повторно.

- `logistics_total = delivery`;
- `reverse_logistics = rebill`;
- `direct_logistics = delivery - rebill` (расчётный остаток, **не подтверждение привязки к продажам**).
- При `rebill > delivery` прибыль блокируется вместо выдумывания значения.
- Клиентская выплата вычитает общий логистический конверт один раз.
- Прибыль по товарным строкам не публикуется до проверки распределения логистики по srid.

Для недели 28.09–04.10 при текущих числах: всего 159657.50, дополнительная 26156.44, расчётная прямая 133501.06. Требуется исходная детализация WB для подтверждения, что rebill действительно входит в delivery, а остаток относится только к продажам. В противном случае схему необходимо уточнить.

Не считать production-ready до проверки исходных WB строк и тестов.
